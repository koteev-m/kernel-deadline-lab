# Kernel deadline lab

A manually dispatched capability check for a disposable offline x86-64 Ubuntu guest. One standard public Linux runner builds a guest with Canonical's signed archive metadata and the pinned Noble 6.8.0-48.48 kernel packages. KVM is required.

The guest boots with systemd and no network adapter. Its two synthetic veth endpoints exchange random UDP messages. An immutable 20-second boot-clock cutoff is compiled into a software traffic classifier at each transmitting end. A separate network namespace exercises a reversible nftables transaction. The runner observes guest reboot and ACPI suspend/wake over serial and QMP. A second serial boot must return the same disk challenge and report a new boot identifier. Output contains fixed test results, package versions and aggregate measurements. No raw identifiers, packet captures, image uploads, credentials, caches or artifacts are part of the workflow.

The nine checks cover KVM, guest ABI, PID 1, offline topology, classifier attachment, packet delivery across the cutoff, nftables isolation, reboot, and suspend. This is a short environment preflight.

## Full native campaign

The manual campaign uses one standard public runner. Each series boots the same authenticated image under KVM with an independent temporary disk overlay and no NIC. Up to four guests run at a time. Each ticket contains a single guest boot-clock deadline exactly 600 seconds from issue. Normal, absent-permit, delayed, stopped-installer, expired-install, installer-loss, wall-clock and ACPI S3 cases keep the original interval. A separate guest reboots while traffic is flowing and tries its old ticket.

Synthetic IPv4 and IPv6 traffic includes persistent and short-lived TCP streams, UDP, and a child sending via pre-existing sockets after changing its network namespace. Receiving-side captures, application timestamps, retransmission counters, loaded program identity, kernel test-run and independent controls distinguish measured delivery from a queued frame. The test examines the effect of privileged classifier removal only inside a disposable network namespace. Captures and generated credentials stay in the disposable guests. Only numeric measurements, versions, program tags and fixed outcomes appear in the job log and summary.

The optional final series uses the upstream 26.11.9 x86-64 proxy binary from a SHA-256-pinned release. Both ends of the VLESS/TLS connection and its generated certificate exist only inside the offline guest. It runs after the synthetic measurements when the normal comparator and filtering prerequisites hold and no synthetic delivery violation was found. The 75-minute job budget covers four bounded guest waves of up to 820 seconds plus disk construction and shutdown. No artifacts, caches or automatic retries are used.

The single-guest inspection workflow preserves the original capture invocation for diagnosis. The campaign first qualifies its measurement path in one guest using a separately labeled 35-second ticket. Only a successful assessment permits the full 600-second trials on the same built disk. The receiver binds a Linux AF_PACKET socket to the individual veth, requests ingress-only delivery and records kernel nanosecond receive timestamps in cooked-v2 pcap format. The assessor reconciles the completed file with kernel packet/drop counters and the application witnesses. No captures are uploaded.

### Established TCP retransmission measurement

On four dedicated sockets (one per address family and direction), the application writes a single 48-byte payload ten seconds before the immutable deadline. After the handshake each private input chain drops only ACKs for its own probe tuple. The receiver reads the original payload once. A read-only tc observer returns UNSPEC and journals the sequence range, ACK and CLOCK_BOOTTIME at sender egress before the deadline filter and at receiver ingress. The incoming packet capture supplies a separate record of the payload and sequence. A repeat reaching the receiver **before** expiry qualifies the positive control. A repeat **after** expiry must appear before the gate, with no matching peer delivery. The same socket cookie, inode, PID, unacknowledged data, bytes acknowledged and TCP_INFO retransmission increments are required. The guest build checks the UAPI layout. Probe maps are private to the four hooks and overflow fails the measurement.

Linux 6.8 breaks out of tcp_write_xmit on local transmit error before accounting new data as outstanding. A write attempt alone therefore cannot exercise the retransmission queue. The prior run did not sample outstanding bytes for a chosen range.
